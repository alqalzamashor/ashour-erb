نسخة ERP محاسبية وإدارية محلية تعمل بـ Python/Flet وSQLite، مع دعم متعدد الفروع ومراكز التكلفة والصلاحيات الدقيقة.

### تعدد الفروع
كل فاتورة مبيعات أو مشتريات، حركة مخزون، سند قبض/صرف، تسوية جرد، قيد يومي، وسطر قيد يمكن ربطه بالفرع ومركز التكلفة.

- المستخدم غير المدير يرى ويعمل فقط على الفروع المسموحة له.
- المخازن مرتبطة بالفروع.
- أرصدة المخزون قابلة للفصل حسب الفرع.
- التقارير والـDashboard قابلة للتصفية حسب الفرع ومركز التكلفة.
- البيانات القديمة يتم ربطها تلقائياً بالفرع والمركز الافتراضيين أثناء التهيئة دون حذف البيانات.

## التشغيل (سيرفر سحابي / محلي)
البرنامج بقى سيرفر ويب فقط - المستخدمون بيدخلوا من المتصفح. راجع **README_SERVER_AR.md** (Docker، HTTPS، PostgreSQL، وكيل الطباعة، وبوابة التجارب لإنشاء قواعد بيانات تجريبية برابط تسجيل).

## التثبيت والتشغيل والاختبارات
- Docker: `docker compose up -d --build`. ويندوز: `install_windows.bat` ثم `run_server_windows.bat`. لينكس: `install_linux.sh` ثم `start_server_linux.sh`.
- الاختبارات: `pip install -r requirements-dev.txt` ثم `pytest -q`. على PostgreSQL: اضبط `ERP_TEST_PG_URL=postgresql://user:pw@host:5432/erp` (القاعدة بتتمسح وتتعمل من جديد، فاستخدم قاعدة اختبار فقط).
- `ERP_HOME` بيغيّر مكان البيانات والنسخ الاحتياطية.

## التشغيل اليومي (ميزات جديدة)
- **ملصقات الأصناف**: المخزون ← «ملصقات الأصناف والأسعار». اختار الأصناف وعدد النسخ والمقاس (حراري أو ورق A4 ملصقات)؛ الباركود EAN-13 لو الباركود صحيح وإلا Code128 بكود الصنف.
- **رسائل واتساب/SMS**: الإدارة ← «الرسائل». المزوّدات: واتساب Cloud (ميتا)، Twilio، أي بوابة SMS عبر HTTP. إيصال بعد البيع بيتبعت **بس للعميل اللي فعّلت له «موافق على استلام رسائل»**، وتنبيه نقص مخزون يومي للمسؤولين. واتساب بيقبل النص الحر خلال 24 ساعة من رسالة العميل؛ غير كده لازم قالب معتمد من ميتا (خانة اسم القالب).
- **طلبات التوصيل**: المطاعم ← «طلبات التوصيل». فعّل المستقبل وأضف مصدر (هنقرستيشن/جاهز/...) هتاخد رابط ومفتاح سري؛ التطبيق بيبعت POST JSON على `http://السيرفر:8600/hook/<المصدر>` بترويسة `X-Api-Key`. الشكل العام موضح في الشاشة ولو شكل التطبيق مختلف عدّل «خريطة الحقول». قبول الطلب بيفتحه دليفري ويبعته للمطبخ. لازم HTTPS (ngrok/nginx) لو هيتفتح للإنترنت.
- **كاشير بدون اتصال**: لو السيرفر/قاعدة البيانات وقعت وقت البيع، البيع **النقدي** بيتخزّن على جهاز الكاشير وبيتزامن تلقائي لما الاتصال يرجع (من غير تكرار فواتير). مش متاح: السداد المتعدد، الشبكة، الخصومات والكوبونات، الولاء، الآجل. الفاتورة الضريبية الرسمية بتتولّد عند المزامنة.

## المحاسبة والامتثال (ميزات جديدة)

- **أعمار الديون وحدود الائتمان**: تقرير "أعمار الديون" (عملاء/موردين) بشرائح 0-30/31-60/61-90/+90 مع تصدير Excel/PDF. على كارت العميل: حد ائتمان، أيام سماح، وإيقاف ائتماني. البيع الآجل اللي يتخطى الحد أو فيه فواتير متأخرة بيتوقف، إلا لو المستخدم معاه صلاحية `credit:override` أو فيه موافقة معتمدة. رصيد العميل بيتحسب من المستندات (فواتير − سندات − مرتجعات على الحساب).
- **دورة الموافقات**: فواتير الشراء، سندات الصرف، تسويات المخزون وتجاوز حد الائتمان لو فوق الحد المحدد في شاشة "الموافقات" بتطلب موافقة. المستخدم يبعت طلب، المعتمد يوافق، وبعدها يعيد نفس العملية. الموافقة تُستهلك مرة واحدة وتنتهي بعد المدة المحددة (افتراضي 48 ساعة). المعتمد يتخطى الطلب ويُسجَّل في سجل التدقيق. الخصومات في الكاشير عليها نظام موافقة المدير القديم.
- **تعدد العملات**: العملة الأساسية SAR. أضف عملات وأسعار صرف يومية من شاشة "العملات". الفواتير والسندات بعملة أجنبية بتتحول بسعر يوم المستند، والدفاتر دايمًا بالأساسية. "إعادة التقييم" تحسب فروق العملة (محققة وغير محققة) وتسجل قيدًا بأرباح/خسائر فروق العملة.
  - أسعار الأصناف الافتراضية بالعملة الأساسية، فاكتب السعر بالعملة الأجنبية يدويًا.
  - طباعة PDF للفاتورة لا تعرض العملة الأجنبية، وتقرير الأعمار لا يحتسب تسويات الفروق.
- **ZATCA المرحلة الثانية**: غير مُنفَّذة. الموجود هو QR المرحلة الأولى مع إرسال تجريبي بسيط (`erp_app/zatca.py`). المرحلة الثانية تحتاج XML بصيغة UBL 2.1 وتوقيع ECDSA بشهادة CSID وتسجيل الجهاز (onboarding) واختبار على sandbox هيئة الزكاة، وده يحتاج بيانات منشأتك.

## النسخ الاحتياطي الخارجي والترقية الآمنة

### رفع النسخ خارج الجهاز (شاشة "النسخ الاحتياطي والاسترجاع" ← "النسخ الاحتياطي الخارجي")
كل نسخة (يدوية أو تلقائية أو أمان قبل ترقية/استرجاع) بتترفع تلقائيًا في الخلفية لكل مكان مفعّل. لو الرفع فشل بيعيد المحاولة لوحده كل نص ساعة طالما البرنامج مفتوح (أو شغّل أمر sync)، والنسخة المحلية سليمة دايمًا. الأماكن:
- **مجلد شبكة / قرص خارجي / مجلد مزامنة**: اكتب المسار بس (مثال `\\server\backups` أو `/mnt/nas/erp`).
- **S3**: AWS S3 أو Cloudflare R2 أو Wasabi أو MinIO. اكتب Endpoint وRegion وBucket ومفتاحي الدخول. فعّل Path-style مع MinIO/R2. التوقيع SigV4 متطابق مع مكتبة AWS الرسمية (اختبار موجود).
- **Google Drive**: (أ) حساب شخصي: محتاج OAuth Client (من Google Cloud Console، واجهة Drive API) وRefresh Token بصلاحية `drive` وFolder ID. (ب) Service Account لـ Shared Drive: شارك المجلد مع إيميل الحساب والصق ملف الـ JSON أو مساره. ملاحظة: حسابات الخدمة ملهاش مساحة تخزين خاصة، فمع Drive شخصي استخدم (أ).
- **التشفير** (اختياري): AES-256-GCM بكلمة سر قبل الرفع. **لو ضاعت كلمة السر النسخ المشفّرة مستحيل تتفتح**. حتى لو التشفير مفعّل، الملفات اللي على الجهاز نفسه غير مشفّرة.
- "عدد النسخ البعيدة المحفوظة" بيمسح الأقدم من المكان البعيد (نسخ الأمان قبل الترقية/الاسترجاع ما بتتمسحش).
- **استرجاع من نسخة بعيدة**: "عرض النسخ البعيدة" ← "جلب للجهاز" (بيفك التشفير ويفحص السلامة) ← بعدها استرجعها من جدول النسخ المحلية.
- من سطر الأوامر (لجدولة خارج البرنامج): `python -m erp_app.backup_remote status|sync|test s3|list gdrive`.
- حدود: الرفع بطلب واحد (S3 حد 5GB للملف الواحد).

### ترقية البرنامج بأمان (`update.py`)
اقفل البرنامج/السيرفر تمامًا، وبعدين:
```
python update.py الإصدار_الجديد.zip --check     # يعرض اللي هيتغيّر بس
python update.py الإصدار_الجديد.zip             # ترقية (ويندوز: اسحب الـ zip على update_windows.bat ؛ لينكس: ./update_linux.sh ملف.zip)
python update.py --rollback --with-db           # رجوع للإصدار السابق (والقاعدة)
python update.py --status                       # الإصدار وسجل الترقيات
```
اللي بيحصل: فحص الحزمة (zip سليم، مسارات آمنة، إصدار أحدث) ← التأكد إن القاعدة مش مفتوحة (SQLite) ← نسخة احتياطية للقاعدة (`pre_update`، وبتترفع للمكان الخارجي لو متفعّل) + لقطة zip للكود (آخر 5) ← استبدال ملفات الكود مع بقاء `data/` و`backups/` و`exports/` ← فحص (تجميع الكود، ترحيل القاعدة بالكود الجديد، استيراد البرنامج) ← لو أي خطوة فشلت: رجوع تلقائي للكود القديم واسترجاع نسخة القاعدة. لو الحزمة من رابط: `--sha256` إجباري. لو `requirements.txt` اتغيّر: `--install-deps`.

## التحليل (ميزات جديدة)

- **لوحة الإدارة**: بقى فيها (1) شريط التنبيهات الذكية، (2) **مقارنة فترات** (الفترة السابقة بنفس الطول، أو نفس الفترة العام الماضي) للمبيعات والمصروفات والأرباح والهوامش وعدد الفواتير ومتوسط الفاتورة والنقدية بأسهم ونسب تغيّر ملوّنة، (3) **التدفق النقدي** (رصيد أول وآخر الفترة، تشغيلي/استثماري/تمويلي، وصافي التغيّر الشهري). التدفق النقدي مبني على تصنيف الحسابات في شجرة الحسابات (حقل "نوع التدفق النقدي")، وأي حساب غير مصنّف يتحسب تشغيلي.
- **التنبيهات الذكية** (الرئيسية ← التنبيهات الذكية): صنف راكد (له رصيد ولم يُبَع من X يوم، والمبلغ المجمّد)، صنف قارب ينفد (وصل لحد الطلب أو يكفي أقل من Y يوم بمعدل البيع في آخر Z يوم، أو نفد وله مبيعات)، عميل متأخر في السداد (حسب تاريخ الاستحقاق = تاريخ الفاتورة + أيام سماح العميل)، عميل تعدّى حد الائتمان أو موقوف ائتمانيًا. العتبات قابلة للتعديل، وفيه **ملخص يومي** واتساب/SMS للمسؤولين عن طريق إعدادات "الرسائل" (لازم تكون مفعّلة بمزوّد). معدل البيع محسوب من مبيعات الفواتير والكاشير فقط (مش التحويلات والتوالف).
- **صلاحيات الحقول**: من شاشة المستخدمين (إضافة/تعديل) اختار إخفاء **سعر التكلفة وقيم المخزون** و/أو **الأرباح والهوامش** عن المستخدم. مستخدم المبيعات الجديد بيتخفى عنه الاتنين افتراضيًا (ومستخدم المخزون: الأرباح فقط). **المستخدمون الحاليون ما اتغيّرش حاجة عندهم** (بيشوفوا زي ما كانوا) لحد ما تعدّل صلاحياتهم. المدير يشوف كل حاجة دايمًا. التغيير بيسري عند تسجيل الدخول الجاي.
  - **الإخفاء مطبّق في**: شاشة الأصناف (عمود وحقول التكلفة)، رصيد المخزن (قيمة الرصيد)، حركة الأصناف، لوحة الإدارة ومقارنة الفترات (الأرباح والهوامش وقيمة المخزون)، تنبيه الراكد (المبلغ المجمّد)، وتصدير Excel/PDF لتقارير المخزون والجرد وتصدير الأصناف ووحدات الأصناف. ومحمي في الخدمات: المستخدم المخفي عنه التكلفة ما يقدرش يحدد تكلفة صنف جديد (بتتسجل صفر) ولا يغيّر تكلفة صنف موجود (من شاشة الصنف أو وحداته أو الاستيراد).
  - **الحسابات الداخلية ما بتتأثرش**: بيع مستخدم مخفي عنه التكلفة بيسجّل قيد تكلفة المبيعات بالتكلفة الحقيقية (متأكد باختبار).
  - **مش مغطى** (بيظهر فيها التكلفة/الربح لو المستخدم معاه صلاحية الشاشة نفسها): تقرير تكلفة الوصفات، تسوية الجرد على الشاشة وفواتير الشراء (سعر الشراء اللي بيدخله المستخدم)، التوالف، تقارير الأرباح المحاسبية (قائمة الدخل، ميزان المراجعة، تحليل المبيعات)، الرواتب والعقود. دي بتتحكم فيها صلاحيات الشاشة (عرض) زي ما كانت.
